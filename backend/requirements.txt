accelerate>=0.31.0,<1.15.0
# 4-bit NF4 quantization. BOTH bounds are load-bearing — this sits in a narrow
# window between two independent constraints, which is why it is pinned exactly:
#   * >= 0.43.2 — transformers 4.49 calls .to() on a 4-bit model and older
#     bitsandbytes rejects it ("Calling `to()` is not supported for `4-bit`").
#   * <  0.49   — 0.49.x calls torch.library.impl_abstract, which does not exist
#     until torch 2.2; against the torch 2.1.2 pinned above it raises
#     AttributeError at import. transformers imports bitsandbytes lazily, so it
#     surfaces as an unrelated "Failed to import
#     transformers.integrations.bitsandbytes" the first time a quantized model
#     loads — which took down Qwen, Qwen-VL and the entire poster pipeline.
# An unbounded ">=0.43.1" is what let pip install 0.49.2 and break everything.
# 0.43.2 and 0.45.5 are both verified working against torch 2.1.2 here, so this
# is a range rather than an exact pin — pinning one version would force a
# needless downgrade of an environment already running a working one.
# Do not widen the upper bound without moving torch first.
bitsandbytes>=0.43.2,<0.49
